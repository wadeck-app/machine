# Audit Report -- completeness -- Machine Network

**Date:** 2026-11-14
**Spec version:** v0.4
**Auditor:** independent reviewer (spec mode); the reviewer could not write files, the text was saved by machine-owner (not every line reference re-checked).

## Scope

`.claude/specs/2026-11-13_machine-network/` (`_index.md`, `guiding-principles.md`, `out-of-scope.md`, `threat-model.md` v3.0, `decisions-pending.md`; `evidence.md` by headings and targeted greps) and `.claude/plans/2026-11-14_machine-network-phase1.md`.

## Executive summary

The spec is strong on security rationale but has almost no implementable interface definition: no wire protocol, no CLI grammar, no data schemas, no config schema, no error catalogue, no exit-code table and no numeric limits. Several release-gating threats (T-04, T-15, T-34, T-24) are still Open with no design. An engineer could not implement the `ls` / `ipconfig` scenario without inventing most of the protocol, the data formats and the first-machine bootstrap.

## New open questions raised

1. Which Noise pattern, crypto library and canonical encoding, and two keys (X25519 and Ed25519) or one derived seed?
2. How does a policy signed on machine A reach target B, and how does A learn B's current version?
3. What does a "call" count (accepted, started, completed), and is the counter per entry, per peer or global?
4. When a connection drops mid-command, does the target kill the child, let it finish, or report on reconnect?
5. How is the externally reachable address of a daemon determined and published behind NAT or on a work network?
6. Is renaming a machine an admin-signed re-registration, and are names unique network-wide?
7. How does the encrypted admin key file reach a new machine (decision 23), and through which channel?
8. How are a remote command's exit code and machine's own exit codes distinguished in `machine run` and `--json`?
9. Which shell invocation form per OS preserves the exact approved string, and what PATH does the scrubbed environment carry?
10. Which browser-compatible KDF and crypto does the admin page use, given WebCrypto lacks scrypt and argon2?
11. What are the default numeric values (timeouts, output cap, concurrency, pre-auth limits, unlock window, registration validity, audit retention)?
12. Which allowlist entries and shell does the acceptance scenario use on each machine (`ls` on cmd needs Git's ls.exe)?
