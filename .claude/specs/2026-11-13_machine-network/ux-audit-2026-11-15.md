# UX audit of init, onboarding, offboarding (2026-11-15)

Source: `npm run test:relay` against the real relay (poc-node `server.js`), transcripts captured with `MACHINE_RELAY_TRANSCRIPT`. Texts below are the output after the fixes unless marked BEFORE. Urls, uuids and ids shortened.

## Relay contract differences found (also in relay-api.md corrections to make)

| Field | relay-api.md / old fake | Real relay | Client change |
|---|---|---|---|
| candidacy `createdAt`, `expiresAt` (post answer, admin list) | epoch seconds | ISO 8601 string | `relayClient` converts to epoch seconds, refuses anything else naming the field |
| inbox document `storedAt` | epoch seconds | ISO 8601 string | same |
| machine `lastSeen` (list, one) | epoch seconds or null | ISO 8601 string or null | same (before: silently ignored, "last seen" never shown) |
| `POST .../heartbeat` before the first record | 200 | 404 `not_found` "No address record for this uuid yet: write it first with PUT /api/machines/<uuid>." | `inboxLoop`: heartbeat asked again after the record is published, inbox read anyway |
| heartbeat of a token that does not own the uuid | 200, count 0 | 403 `not_owner` | `inboxLoop`: treated like the inbox read (a state, no backoff) |
| inbox page | `next` absent on last page | `next: null`, `success: true` | none needed |
| `serverTime` | epoch seconds | ISO string | not read by the client |
| `verificationUrl` of the device login | full url | `http://127.0.0.1/manage#/tokens` (port dropped, on a non-default port) | none; relay owner to check |

`fakeRelay.ts` now answers like the real relay for all of the above.

## Not fixed (decisions or other owners)

- Relay: `verificationUrl` drops the port (poc-owner).
- The revoked machine itself is never told it was revoked (design: peers are told, it learns it through refusals).
- The web admin page (app-module) still lists the candidacy code column; its final-code component is renamed "Security code" and shows the new digits (same twin).
- `admin sign-policy` keeps exact UTC bounds in the signed policy summary on purpose (signature review).

## Fixed by the second pass (2026-11-15, decisions 55 and 56)

One meaningful code per moment (relay login code, pairing code, security code), local times with a relative hint, `list` naming the daemon command, revoked machines named by `forget-relay-record` and listed by `status`. Texts above are the output after the fixes.

## Real behaviours worth knowing

- Reusing an identity key: the same token re-posting replaces the pending entry (same id, new random).
- The relay answers the revoked machine's heartbeat `403 not_registered` after the revoke (record and binding removed).
- Not tested: 15 minute relay-side expiry (client clock moved instead), `too_many_machines` (needs 51 machines), the 5 per 10 minutes limits (each request uses its own source address via `X-Forwarded-For`).
