# `machine install idle-suspend`

Decisions 101, 102, 103, 105, 106, 109, 111 and 113 (user concerns 2026-11-22, 2026-11-24, 2026-11-25). Item of `machine install` (see `install.md` for the lifecycle). Linux only. Suspends the box when it is REALLY idle, independent of session state.

Why: on `thinkcentre` (xrdp) logind's `IdleAction=suspend` never fires: the xrdp session keeps `IdleHint=no` and survives the RDP disconnect. Disconnected sessions must stay (they hold open windows), so the decision is made outside logind.

## Files (root-owned, each carries the marker `# managed by machine install idle-suspend, version 8`)

| File | Mode | Content |
|---|---|---|
| `/usr/local/bin/machine-idle-suspend` | 0755 | POSIX sh generated by `idleSuspendScript` (machine-core); the validated integer minutes, the whitelisted config folder and absolute tool paths are the only interpolations |
| `/etc/systemd/system/machine-idle-suspend.service` | 0644 | `Type=oneshot`, runs the script, `TimeoutStartSec=25` (a oneshot has no start timeout by default: a hung pass would stop every later one; 25 s is under the shortest cadence), `StandardOutput=null` (the script logs itself) |
| `/etc/systemd/system/machine-idle-suspend.timer` | 0644 | `OnBootSec=2min`, `OnUnitActiveSec=30s`, `1min` or `2min` (the cadence, see below), `AccuracySec=1s`, `WantedBy=timers.target` |

- Install steps: stage, `sudo install` x3, `daemon-reload`, `enable`, `restart` the timer; verified with `systemctl is-active` (no sudo). Remove: `disable --now`, `rm` timer, service, script, `daemon-reload`; post-check as in `install.md`.
- `--ssh-minutes <1..1440>` (default 20, decisions 109 and 111: the INPUT idle time of the tty of an ssh session) lives in the script (`SSH_MINUTES=<n>`) and is kept like `--rdp-minutes`. `--rdp-minutes <1..1440>` (default 20, decision 103) lives in the script (`RDP_MINUTES=<n>`) and is kept like `--minutes`. `--minutes <1..1440>` (default 30, 1 allowed, see below) lives in the script (`MINUTES=<n>`), the units do not depend on it. Without `--minutes` an installed script keeps its minutes (a status never calls it outdated for that); with it, the script is replaced after the usual display.
- Needs `ss`, `systemd-inhibit`, `logger`, `date` (absolute paths measured with `command -v`); a missing one is `unsupported here` with the package named. `journalctl` is optional (status only).
- No sudoers rule, no peer command: the script runs as root from systemd. It is independent of the `suspend` item.

## Cadence and wake grace (decision 113)

- NO `sleep` in the script: one pass is one run of the timer. The cadence comes from the SMALLEST of `--minutes`, `--rdp-minutes`, `--ssh-minutes` (`idleCadenceSeconds`, machine-core): below 10 min every 30 s, 10 to 30 min inclusive every 1 min, above 30 min every 2 min. It is written in the timer text, so changing any of the three options changes the timer: `--refresh` rewrites it; `--check`, `status` and the list say `outdated` and name the cadence of the installed timer against the one the options give.
- Timer semantics (systemd.timer(5), from documentation, NOT yet observed on the box): `OnUnitActiveSec` is relative to the last activation (start) of the service, so passes are one cadence apart start to start; `OnBootSec=2min` runs the first pass 2 min after boot; `AccuracySec` lets systemd delay an elapse by up to that much to coalesce wakeups (default 1 min would swallow a 30 s cadence), hence `AccuracySec=1s`. A pass can still be late under load or after a resume: the logic counts in seconds, never in passes.
- The confirmation is the NEXT pass (the state `<since> <last>` proves the other checks passed on the previous pass). Delays after the last input, for a box that then stays idle (`idleSuspendDelaySeconds`, printed by `--dry-run`, `--check` and `status`):

  | Cadence c | With RDP (N = `--rdp-minutes`) | Without RDP (N = `--minutes`, input N then the N timer) |
  |---|---|---|
  | 30 s | N + 0.5 to N + 1 min | 2N to 2N + 0.5 min |
  | 1 min | N + 1 to N + 2 min | 2N to 2N + 1 min |
  | 2 min | N + 2 to N + 4 min | 2N to 2N + 2 min (N odd: 2N + 1 to 2N + 3 min, the timer ends on a pass 2 min apart) |

  Examples: 30/20/20 (1 min): 21 to 22 min with RDP, 60 to 61 min without. 9/9/9 (30 s): 9.5 to 10 min and 18 to 18.5 min. 60/45/40 (2 min): 47 to 49 min and 120 to 122 min.
- The N-minute timer (`since`), the ssh rate sample age (300 s, always at least one cadence) and the audit window are in seconds: the behaviour is the same at every cadence (core test with a pass simulator at 30 s, 1 min, 2 min). The state gap rule is relative to the cadence: a gap above `max(300 s, 10 x cadence)` (300, 600, 1200 s) since the last pass restarts the confirmation.
- Journal volume: one line per pass as before (every decision goes to the journal): 2880 lines a day at 30 s, 1440 at 1 min, 720 at 2 min.
- WAKE GRACE: `--wake-grace-minutes <1..60>` (default 5, `WAKE_GRACE_MINUTES=<n>` in the script, kept like the other options). After every resume nothing suspends for that long, whatever the readings (xprintidle counts the sleep, so right after a wake every reading says idle). It is checked AFTER all the other checks (an earlier failing check keeps its own reason) and clears the timer state like any not-idle verdict, so after the grace one pass only confirms, the next suspends. Journal: `not idle: wake grace (N min left)` (rounded up).
- RESUME DETECTION, at EVERY pass before any check: the kernel counter `/sys/power/suspend_stats/success` (validated on the box: +1 per suspend, 37 to 39 across two suspends, equal to the `PM: suspend entry` lines of the kernel journal) is compared with the record `/run/machine-idle-suspend/resume` (`<counter> <epoch it was first seen>`, or `unreadable <epoch>`; NOT cleared by a not-idle verdict, cleared by a reboot with /run). A counter different from the record (greater, or lower after a reset), no record or an unusable record is a resume NOW: the grace starts at that pass, so at most one cadence after the real wake (the grace counts from that first pass). A record from the future (the clock went back) restarts the grace from now, bounded by G.
- Unreadable counter (missing, not a whole number): treated as a resume ONCE, fail closed, with the cause on the line (`(resume detection off: cannot read /sys/power/suspend_stats/success (missing or unreadable))`). The record becomes `unreadable <epoch>` and keeps the start of that grace, so a permanently unreadable counter blocks for the grace only (G min) and never again; every later line of every pass (not idle, idle, suspending) still ends with the cause, never silent. A counter readable again after an unreadable record is adopted as the baseline without a new grace; a counter that was readable and no longer is starts one new grace (a resume cannot be excluded). Residual: a counter that flaps readable/unreadable restarts the grace at each loss (loud, bounded by G each time). A record that cannot be written exits 1 without suspending (`cannot write /run/machine-idle-suspend/resume: not suspending`).
- The other resume protection stays: state absent, unusable, clock back or a gap restart the confirmation (`confirming at the next check`). Script version 8; the sudoers is untouched.

## Decision (`idleDecision(facts, now, minutes)`, pure; the script takes the same decision)

Checks in this order; the first that fails is the reason and clears the state file. An input that cannot be read is NOT idle (never a suspend on an error).

| # | Check | Reason (journal) |
|---|---|---|
| 1 | Keep-awake files `/run/machine-keep-awake` and `<config dir>/keep-awake`: any content keeps awake; first line `until <epoch>` or `keep awake until <epoch>` (1 to 12 digits) only while `epoch > now`, a past epoch is ignored | `keep-awake requested`; unreadable: `cannot read the keep-awake files` |
| 2 | `ss -Htn state established`, LOCAL port 3389 (rdp), 22 (ssh), or the `peerPort` of `<config dir>/daemon.port.json` (absent file: no peer port; garbage: unreadable). The peer always counts. rdp counts only while the X input idle time (see below, decisions 102 and 103) is under R min (`--rdp-minutes`, default 20). every ssh connection is tested (decision 111): a login WITH A TTY (pts) counts only through a session whose input idle time (see below) is under S min (`--ssh-minutes`, default 20), its traffic is ignored; a login WITHOUT a tty (`@notty`) counts while the average rate of its TCP connection since the previous check is at or above 2048 B/s, or unknown (see below) | `ssh session pts/1 active (input 3 min ago, needs 20)`, `ssh connection <peer> active (5000 B/s, needs 2048)`, `ssh connection <peer> rate unknown (<cause>)`, `ssh connected (cannot read the ssh state: <cause>)`, `machine peer connected`, `rdp connected (input 3 min ago, needs 20)`; unreadable: `cannot read the connections (ss or the daemon port file)`; rdp fail closed: `rdp connected (xprintidle is not installed: sudo apt install xprintidle)`, `rdp connected (input idle unreadable: <cause>)` |
| 2b | No RDP connection (decision 103): the X input idle time must be at least N min when it can be read (not readable: the timer rule alone, said in the journal line, see below) | `input 2 min ago (needs 5)` |
| 3 | Last 2000 lines of `<config dir>/audit.log`: an `accepted`, `completed` or `held` entry newer than N min, or a `held` (under 2 h old) without a `hold-ended` of the same id | `machine request in the last N min`, `machine request on hold`; unreadable or missing log, damaged timestamp: `cannot read the machine audit log` |
| 4 | 5-min load average (`/proc/loadavg`, hundredths) under 0.30 | `load 0.45 (limit 0.30)`; unreadable: `cannot read the load average` |
| 5 | No `systemd-inhibit --list` line that covers `sleep` and ends in `block` (a delay inhibitor, or a block on `idle` or `handle-*-key` only, does not count) | `sleep inhibitor held (block)`; failure: `cannot list the sleep inhibitors` |

All 5 pass: the timer runs on `/run/machine-idle-suspend/since` (`<since> <last check>`, epoch seconds).

| State file | Result |
|---|---|
| absent | `idle 0/N min`, since = now |
| unusable (garbage, since after last) | `idle 0/N min (timer restarted: the state file is unreadable)` |
| since or last in the future | `... (timer restarted: the clock went back)` |
| last check more than `max(300 s, 10 x cadence)` ago (300, 600, 1200 s) | `... (timer restarted: no check for more than 5, 10 or 20 min, the box slept or was off)` |
| elapsed whole minutes < N | `idle 12/30 min` |
| elapsed >= N | `suspending: idle 31 min`, state file removed, `systemctl --no-block suspend` |

- Resume protection: the kernel counter and the wake grace (decision 113, above), then the gap rule as a second net (no extra systemd-sleep hook file).
- A disconnected xrdp session is NOT activity. An ESTABLISHED RDP connection is activity only while the session has had input in the last R min (decisions 102 and 103; before it, any RDP connection counted, so an open window kept the box awake for ever).
- Input idle time (decisions 102, 103, 105; read at every check), measured per logind SESSION, not per X socket (the greeter display `:0`, owned by root, has no xprintidle answer and made decision 102 never act): `loginctl list-sessions --no-legend`, then `loginctl show-session <id> -p Name -p Type -p Display -p Class -p State` (`loginctl show` alone is not supported on the box). Kept: `Class=user`, `State` active or online (a closing session is dropped), a non-empty `Display` (`:<n>`); its `Name` must match `^[a-z_][a-z0-9_-]{0,31}$` (the installing-user pattern) and its home is field 6 of that user in `/etc/passwd` (safe absolute path). For each: `DISPLAY=:<n> XAUTHORITY=<home>/.Xauthority runuser -u <name> -- xprintidle` prints milliseconds; the input idle time is the MINIMUM over those sessions, in whole seconds. `Remote` is not read (nothing depends on it). Tools `loginctl`, `runuser`, `xprintidle` are absolute paths from `command -v` at install time, else `/usr/bin/loginctl`, `/usr/sbin/runuser`, `/usr/bin/xprintidle`, checked with `-x` at each run (so installing xprintidle later works without a refresh). `stat` serves only the ssh tty rule (decision 111, below).
- An X socket of `/tmp/.X11-unix` that no kept session uses (the greeter, a closing session) is IGNORED on purpose and said, only next to a measured input idle time: `(ignored display :0: no user session)` or `(ignored displays :0, :1: no user session)`, at the end of the lines that state the input (`not idle: rdp connected (input 3 min ago, needs 20) (ignored display :0: no user session)`, `suspending: ...`, `idle 12/30 min (ignored display :0: no user session)`).
- Fail closed, with the user and display in the cause: a kept session whose display xprintidle cannot measure is unreadable (`xprintidle failed on :10 as wadeck`).

  | RDP situation | Journal reason |
  |---|---|
  | input idle < R min | `not idle: rdp connected (input 3 min ago, needs 20)` (whole minutes) |
  | input idle >= R min | not activity, and NO N-minute timer: if the other checks passed on the previous check too, `suspending: rdp connected but no input for 25 min (needs 20)`; otherwise (first pass, after a wake, state unusable) `idle: rdp connected but no input for 25 min (needs 20), confirming at the next check` plus the restart cause |
  | xprintidle missing | `not idle: rdp connected (xprintidle is not installed: sudo apt install xprintidle)` |
  | no kept user session (greeter only, only ssh sessions) | `not idle: rdp connected but no user session found` |
  | loginctl or runuser missing, loginctl failing | `... (input idle unreadable: loginctl is not installed (/usr/bin/loginctl))`, `runuser is not installed (/usr/sbin/runuser)`, `loginctl list-sessions failed`, `loginctl show-session c2 failed` |
  | session user not plain, display not `:<n>`, no home | `... unreadable: the name of session c2 is not a plain user name`, `session c2 has an unexpected display`, `no usable home folder for alice in /etc/passwd` |
  | xprintidle errors or prints text | `... unreadable: xprintidle failed on :10 as wadeck`, `xprintidle printed no number on :10` |

- Two thresholds (decision 103), the input is read at every check, with or without an RDP connection:

  | Situation | Rule |
  |---|---|
  | RDP connected | activity while input idle < R (`--rdp-minutes`, default 20, 1..1440); from R on it is not activity and the box suspends at the next check once ssh (tty input) and peer, machine requests (last N min, holds), load, inhibitors and keep-awake pass. The input idle time is the clock: no N-minute timer on top (the 2N latency of decision 102 is gone) |
  | No RDP, input readable | the input idle must be >= N (`--minutes`): `not idle: input 2 min ago (needs 5)`; then the unchanged N-minute timer |
  | No RDP, xprintidle missing, unreadable or no user session | the unchanged timer alone, never silent: every timer line ends with ` (input idleness not checked: xprintidle is not installed)`, ` (input idleness not checked: no user session found)` or ` (input idleness not checked: <cause>)` (`idle 12/5 min (...)`, `suspending: idle 6 min (...)`); status says `note: xprintidle missing, input idleness is not checked, and an RDP connection counts as activity: sudo apt install xprintidle` |

  - Resume protection in RDP mode: the state file (`since last`) is kept as "the other checks passed on the previous check". Absent, unusable, clock back or a gap over `max(300 s, 10 x cadence)` restart it and the line says `confirming at the next check`; so a first pass with an input idle time already >= R never suspends before the other checks have passed once, one cadence later (30 s, 1 min or 2 min); after a wake the wake grace comes first. `since` is not used as a clock in this mode.
  - Without an RDP connection the box still waits for BOTH the input (N) and the timer (N, which starts once every check passes, input included): after the keyboard stops the suspend comes about 2N min later (see the delay table above). Not changed by decision 103.
  - `--minutes` and `--rdp-minutes` are independent; each is kept when the other is changed (`RDP_MINUTES=<n>` and `MINUTES=<n>` in the script).
- Script version 8 (decision 113: cadence, wake grace, resume record; 7 was decision 111 corrected, 6 was decision 111 first wording, 5 was decision 109, 4 was decision 105, 3 decision 103, 2 decision 102): an older script is `outdated` until `machine install idle-suspend --refresh`. The plan never installs xprintidle; `--dry-run`, `--check`, `status` and `--json` say `note: xprintidle found at <path>: ...` or the missing note above; the summary reads `suspends after 5 min idle (RDP: 20 min, SSH: 20 min, no tty: 2048 B/s)` (the threshold of `IDLE_SSH_NOTTY_BYTES_PER_SECOND` is also in `--help`, the `--dry-run` file description and the journal lines).
- Small values (decision 106, lower bound 1 for `--minutes`, `--rdp-minutes` and `--ssh-minutes`, upper 1440, defaults 30, 20 and 20): the timer fires every 30 s, 1 min or 2 min (decision 113), so a value below the cadence behaves as the next check (1 min: the box suspends at the first check after the input idle reaches 1 min, the confirming pass first: 1.5 to 2 min with RDP). Very small values can suspend the box between two commands of a short pause; that is the owner's own choice and only restricts uptime (T-68 unchanged: no network surface, no right for any peer). Only the validation changed: the script text does not, so its version did not change then. The `machine install idle-suspend --help` says the same once.
- The audit lines are matched ANCHORED on `{"seq":..,"prev":..,"entry":{"ts":"..","event":"<e>"`: `ts` and `event` are the first keys the daemon writes, so a command text containing `"event":"accepted"` (escaped in the JSON line) never matches.
- ssh connections (decision 111, corrected 2026-11-24: EVERY connection is tested; replaces the traffic rule of decision 109). Read at every check, only when an ssh connection (local port 22) is established, BEFORE the rdp verdict (the samples must be kept at every run) and judged after it, before the peer check. The script lists them with `ss -Htinp state established '( sport = :22 )'` (root): per connection a line with the Process column (every pid of the login: the `[priv]` parent AND the user process) and, tab-indented, the TCP counters. The title of each pid (`/proc/<pid>/cmdline`, set by sshd) tells the kind: `sshd-session: <user>@pts/<n>` (`sshd: ...` on an older sshd) is a terminal login, `sshd-session: <user>@notty` a login without a terminal (scp, rsync, `ssh host command`, the permanent Herdr stream `ssh -T host 'exec herdr-core connect'`); the `[priv]` title is ignored; a tty that is not `pts/<n>` is unreadable; no recognised title for a connection (no Process column, vanished pid, another ssh server) is a mapping failure. `/dev/pts` is never listed, so a stale pts with no ssh login is never counted.
- pts login: input idle = now - atime of `/dev/pts/<n>` (`stat -c %X`: what `w` and logind read; output does not touch it); the ssh idle time = the MINIMUM over the pts logins (on a tie the first in the order of `ss`), whole seconds. Its traffic is ignored: a terminal printing output is not input.
- notty login: rate = (delta of `bytes_acked` + delta of `bytes_received` of its connection) / seconds between two checks, integer B/s. Active when rate >= THRESHOLD = 2048 B/s (`IDLE_SSH_NOTTY_BYTES_PER_SECOND`, sent + received combined; measured idle Herdr baseline 190 to 230 B/s, ten times margin). The previous sample lives in `/run/machine-idle-suspend/ssh-samples` (`<local> <peer> <epoch> <bytes>`, keyed by local + peer address:port, one line per notty connection, rewritten at every read so the entries of vanished connections are dropped, removed when no ssh connection exists, NOT cleared by a not-idle verdict: otherwise no connection would ever get a rate). The rate is UNKNOWN, which counts as activity for this check (fail closed, the cause in the journal): first sight of the connection, previous sample older than 300 s, counter that went DOWN (a new connection reusing the key), previous sample in the same second, previous sample line damaged, `bytes_acked` or `bytes_received` missing or not a number.

  | ssh situation | Journal reason |
  |---|---|
  | a pts login, input idle < S min | `not idle: ssh session pts/1 active (input 3 min ago, needs 20)` (whole minutes, the freshest tty named) |
  | a notty login, rate >= 2048 B/s | `not idle: ssh connection [::ffff:10.0.0.9]:40000 active (5000 B/s, needs 2048)` (the first in the order of `ss` among the active and unknown ones) |
  | a notty login, rate unknown | `not idle: ssh connection <peer> rate unknown (first check of this connection (no previous sample))`, `(previous sample older than 300 s)`, `(byte counter went down (a new connection on the same address))`, `(the clock did not advance since the previous sample)`, `(previous sample unreadable)`, `(bytes_acked or bytes_received missing or not a number in ss -tin)` |
  | pts logins all idle >= S min | not activity; every timer line (`idle 12/30 min`, `suspending: ...`, the rdp lines) ends with ` (ssh session pts/1 idle for 25 min, needs 20)`, after the input note and the ignored displays |
  | notty logins all under 2048 B/s | not activity; the timer lines end, after the pts note, with ` (ssh connection <peer> quiet: 200 B/s, under 2048)` per connection; a not-idle line from a later check does not carry them |
  | unreadable: no sshd login process for a connection, a title tty that is not `pts/<n>`, `stat` fails or prints no number, an atime in the future, `ss -tinp` fails, the samples file cannot be read or written | `not idle: ssh connected (cannot read the ssh state: no sshd login process (title sshd-session: <user>@<tty>) found for the ssh connection <peer>)`, `... an sshd login process has an unexpected tty in its title (3001)`, `... cannot read the idle time of pts/1 (stat /dev/pts/1 failed)`, `... stat printed no number for /dev/pts/1`, `... the last input of pts/1 is in the future (clock or tty error)`, `... cannot list the ssh connections (/usr/bin/ss -tinp failed)`, `... cannot read /run/machine-idle-suspend/ssh-samples`, `... cannot write /run/machine-idle-suspend/ssh-samples` |

  - FAIL CLOSED: one unreadable connection makes the whole ssh state unreadable, even when another one is idle. Verdict order: unreadable, pts input, notty active or unknown.
  - Cost of fail closed: a connection seen for the first time blocks that check, and every not-idle verdict clears the N-minute timer, so a new connection (a Herdr reconnect after a resume) delays the suspend by a whole timer (N min), or by one check in rdp mode.
  - Unconditional as before: the machine peer port connections and the audit rule (`machine request in the last N min`, holds).
  - Known limit (decision 111, accepted by the owner, T-68): a job over ssh WITHOUT a tty (`ssh host long-command`, scp or rsync of a big file) that stays under 2 KB/s with a low CPU is protected only by load5 under 0.30, sleep inhibitors, machine requests and holds, the keep-awake file, and can be cut by the suspend. Work-arounds: run it in a tty (`ssh -t`, tmux), under `systemd-inhibit --what=sleep`, or write the keep-awake file. A terminal left open with nobody typing is idle after S min.
  - An application keepalive (`ServerAliveInterval`, `ClientAliveInterval`) on a terminal login never touches the tty, so it does not keep the box awake; on a notty login it is the idle baseline (about 200 B/s) and stays under the threshold.
- Peer connections are short-lived (probes close at once); a long-lived peer socket would keep the box awake (check on the box: `ss -Htn state established`).
- Every decision goes to the journal: `logger -t machine-idle-suspend -- <reason>`. `machine install` list, `--check` and `machine status` show `suspends after N min idle` and the last line of `journalctl -t machine-idle-suspend -n 1` when the user can read it, parsed (`last: 18:13:56 not idle: rdp connected (3 min ago)`: no host, tag or pid, local time, age; shown whole when it does not parse, wrapped and never cut; layout in `install.md`), else `not readable by your user` with the `sudo ...` command; never an error. `--json` keeps the raw line.
- A state file that cannot be written, a clock that cannot be read, or a failing `systemctl suspend` exit 1 after logging the cause, without suspending.

## Verified on the real box (thinkcentre, script version 8, 2026-11-26, thresholds 1-1-1)

| Case | Result |
|---|---|

| Wake grace 4 min after a wake | `not idle: wake grace (3,3,2,2,1,1 min left)` from the first pass, `idle` then `suspending` right after it ends |

| ssh terminal (pts) with fresh input, then idle | blocks while typing (`ssh session pts/1 active (input 0 min ago, needs 1)`), no longer after S min, suspends 2 min 16 s after the last input |
| notty ssh stream of 50 KB/s for 3 min | blocks (`active (49635 B/s, needs 2048)`), suspends 1 min 30 s after it ends |

Also verified: the timer (`OnUnitActiveSec=30s`, `AccuracySec=1s`) fires every 30 to 31 s; the first pass after a wake comes about 30 s later (the monotonic timer does not count the sleep); `/sys/power/suspend_stats/success` rises by 1 per suspend and equals the `PM: suspend entry` lines (46 on 2026-11-26); `/run/machine-idle-suspend/resume` follows it; `systemctl --no-block suspend` from the root oneshot suspends (no polkit); the `ss -Htinp` layout and its Process column (user process and `[priv]` parent); a new connection first reads `cannot read the ssh state: no sshd login process ... found` (its process has no final title yet), then `rate unknown`, then a rate: fail closed, one or two passes of delay. A client that types into a suspended box drops with `client_loop: send disconnect` (about 1 min 30 s here); a short suspend (43 s, 55 s) leaves ssh and RDP connected.
